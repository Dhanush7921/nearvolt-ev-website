# NEARVOLT EV V1.1.0: release, safe rollout and rollback

Branch: `upgrade/v1.1-premium-zero-cost` (not merged). `production/v1` is the stable V1.0.
Android details: package `com.nearvolt.ev`, versionCode 2, versionName 1.1.0, minSdk 26 (Android 8.0), targetSdk 36. Firebase project, release signing key, Play Integrity and App Check are unchanged.

## 1. Compatibility matrix (tested)
| App ↓ / Backend → | V1.0 backend | V1.1 backend |
|---|---|---|
| **V1.0 app** | works | Active sessions finish normally. New requests and accepts get `426 UPGRADE_REQUIRED` with an "update the app" message. |
| **V1.1 app** | Works as V1.0. The server advertises no `capabilities`, so the app sends no battery % and shows no PIN screens. | Full V1.1 features |

Evidence:
- Backend test *migration*: legacy sessions start and complete without a PIN on a V1.0 client header, and new work from V1.0 is refused.
- Android `CompatibilityTest`: the V1.1 app's request bodies contain no `batteryPercent` or `pin` keys when those values are absent, so V1.0's strict schemas accept them. A V1.0 config response gives all-false capabilities.

## 2. Session PIN migration policy
- Requests accepted **before** the V1.1 backend is live have no `pinPolicy`. They start and finish without a PIN, so active V1.0 sessions are never interrupted.
- Every request accepted **by** V1.1 gets `pinPolicy: v1.1` plus a PIN. If the PIN is missing on such a request, start is refused with `PIN_UNAVAILABLE`, so there is no bypass. The driver refreshes the PIN (at most 3 times).
- A client cannot downgrade the policy: the policy is set server-side at accept time, and V1.0 builds cannot accept.

## 3. Safe rollout (owner approval required at each step)
1. Build and sign the V1.1 APKs (section 5). Install over V1.0 on all pilot phones; the V1.1 app is safe on the V1.0 backend.
2. When pilot users confirm they've updated, merge `upgrade/v1.1-premium-zero-cost` into `production/v1`. Render redeploys automatically; the health check must show `ready: true`.
3. Raise the minimum version to 2 so stragglers see the update screen. Use **either** method:
   - **Admin dashboard → Settings**: requires admin TOTP MFA (`REQUIRE_ADMIN_MFA=true` in Render, which stays on).
   - **While MFA enrolment is pending**: run the owner-only, audited command on your PC. There is no API for it, and it writes an `auditLogs` entry that appears in the admin Security tab.
     ```powershell
     cd C:\Users\Asus\NEARVOLT-EV\backend
     gcloud auth application-default login
     $env:GOOGLE_CLOUD_PROJECT="nearvolt-ev"
     node scripts/set-app-version.mjs --min 2 --latest 2 --dry-run
     node scripts/set-app-version.mjs --min 2 --latest 2
     ```
4. Smoke test on two phones (host and driver): request, accept, PIN, start, complete, rating.

## 4. Rollback
| Layer | How |
|---|---|
| Backend | Render → Deploys → roll back to the last V1.0 deploy, or `git revert` the merge on `production/v1`. V1.1 apps keep working, because capabilities disappear and they behave like V1.0. |
| Settings | `node scripts/set-app-version.mjs --min 1 --latest 1` (or the admin Settings page) so V1.0 apps are allowed again. |
| Database | No migration is needed. V1.1 only adds optional request fields (`batteryPercent`, `pin`, `pinPolicy`, `pinReissues`), which V1.0 ignores. |
| APK | Not required: V1.1 runs on V1.0. Android blocks installing V1.0 over V1.1, so a downgrade means uninstall then reinstall. |

## 5. Build signed release APKs (Windows PowerShell, existing key)
Signing comes from `android\keystore.properties`, or from the environment variables below for the current window only. No new key is generated.
```powershell
cd C:\Users\Asus\NEARVOLT-EV
git fetch origin
git checkout upgrade/v1.1-premium-zero-cost
git pull
cd android
Test-Path app\src\prod\google-services.json        # must print True
# Only if you do not use keystore.properties:
$env:NV_KEYSTORE_FILE="C:\path\to\nearvolt-release.jks"; $env:NV_KEYSTORE_PASSWORD="…"; $env:NV_KEY_ALIAS="…"; $env:NV_KEY_PASSWORD="…"
.\gradlew.bat clean testDevDebugUnitTest lintDevDebug assembleProdRelease -PNV_PROD_API_BASE_URL=https://nearvolt-api-0rxa.onrender.com/
```
Outputs in `app\build\outputs\apk\prod\release\`:

| APK | Device |
|---|---|
| `app-prod-arm64-v8a-release.apk` | Most phones (2017+); share this one |
| `app-prod-armeabi-v7a-release.apk` | Older 32-bit phones |
| `app-prod-x86_64-release.apk` | Emulators, Chromebooks |
| `app-prod-universal-release.apk` | Any device (~51 MB) |

Verify before sharing:
```powershell
$bt = (Get-ChildItem "$env:LOCALAPPDATA\Android\Sdk\build-tools" | Sort-Object Name | Select-Object -Last 1).FullName
Get-ChildItem app\build\outputs\apk\prod\release\*.apk | ForEach-Object {
  & "$bt\apksigner.bat" verify --print-certs $_.FullName | Select-String "SHA-256"
  & "$bt\aapt2.exe" dump badging $_.FullName | Select-String "package:"
}
# Every APK: the same SHA-256 as the Firebase release fingerprint; package com.nearvolt.ev, versionCode 2, versionName 1.1.0
```
Remove the environment variables afterwards: `Remove-Item Env:NV_KEY*`.

**Telugu/Hindi drafts:** not included by default.
- `-PNV_I18N_DRAFT=true` adds the general UI translations for internal testing.
- Safety/legal strings stay English unless `-PNV_I18N_SAFETY_REVIEWED=true` is set after a native speaker has signed off.
- Review status is in `android/app/src/i18nDraft/REVIEW_STATUS.json`.

## 7. Zero-cost status
Free services used:
- Maps: MapLibre with OpenFreeMap.
- Directions: a Google Maps URL.
- Charts: inline SVG.
- OTP autofill: the SMS User Consent API (Play services, no SMS permission).

Skipped because they cost money:
- Road distance and routing APIs.
- Places search.
- Paid SMS for phone OTP, which stays behind the disabled flag until an approved provider exists.
- Razorpay, a custom domain, Firestore TTL (needs the Blaze plan), Identity Platform billing and paid hosting.
