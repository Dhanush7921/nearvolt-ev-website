## What changed
**Backend (additive)**
- **Capabilities:** `users/{uid}.capabilities {driver, host}` is server-written only. A server-derived `roles` claim sits alongside the unchanged legacy `role` claim.
  - Tokens and records from before V1.4 fall back to `[role]`, so nothing has to be migrated before deploying.
- **`POST /me/capabilities {capability: driver|host}`:**
  - Requires a completed profile and an existing role; only driver or host can be added (anything else, such as admin, is rejected).
  - Idempotent and rate-limited (10/day), and audited (`account.capability.add`).
  - Claims are re-derived from Firestore, so concurrent calls converge and the admin claim is preserved.
  - Host mode does **not** create or approve a listing: the listing starts as DRAFT → submit → admin review, as before.
- **Guards:** `requireRole` now passes on any held capability. Creating a request requires Driver mode (`403 MODE_NOT_ENABLED`). `/hosts/me/*` still requires Host mode.
- **Conflicting operations:**
  - Self-booking is refused at creation and in the transition transaction, and your own listing is excluded from discovery.
  - `HOSTING_ACTIVE`: no driver request while you are hosting an active session.
  - `DRIVING_ACTIVE`: no accepting while your own driver visit is accepted, arrived or charging.
- **Server electrical gate**, checked at creation **and again at acceptance**, for every client version:
  - Missing power, phase or current → `ELECTRICAL_SPEC_INCOMPLETE`.
  - 15 A / 16 A wall sockets need all of the following:
    - a host-declared dedicated circuit (`SOCKET_CIRCUIT_UNCONFIRMED`);
    - single phase, with current and power within the socket rating of 15 A / 3.45 kW or 16 A / 3.68 kW (`SOCKET_OVER_RATING`);
    - the driver's `socketConfirmation` (`SOCKET_CONFIRMATION_REQUIRED`), which older apps cannot send.
- **Other changes:**
  - Nearby results include `dedicatedCircuit` and `currentA`; no location or private data is added.
  - `/public/config` capabilities: `apiLevel 3, dualRole, socketGate`.
  - Admin users list shows capabilities. Broadcasts reach legacy roles and capabilities, each user once.
  - The Sheets `USERS` tab gets a `capabilities` column. The header is rewritten automatically and rows are upserted by UID, so there are no duplicate users.

**Android (reuses existing screens)**
- **Driver / Host switch:** an emerald sliding pill on Home, Account and the host Dashboard. Switching is instant, with no sign-out.
  - The selected mode is stored locally as a UI preference only, and can never exceed the server's capabilities.
  - It is cleared on sign-out and account deletion.
- **Enabling a mode:** a locked mode opens "Become a host" or "Turn on Driver mode", which explains verification. It calls the server, refreshes the token and switches.
  - The switch is hidden on servers without `dualRole`, so V1.4 still works against the current production backend.
- **Navigation:**
  - Driver: Home | Map | Activity | Alerts | Account.
  - Host: Dashboard | Listing | **Activity** (incoming history) | Alerts | Account.
  - Notifications from both modes are in Alerts. Each request opens in the right role from the server's view.
- **Socket confirmation:** sent only when the server advertises `socketGate`. The V1.3 client-side gate is unchanged.
- **VOLT AI in Host mode:**
  - A host-requirements card, based on the server's listing and request rules.
  - Dashboard, Listing and Safety shortcuts.
  - Suggestions that map to reviewed records (dedicated circuit, RCD, extension cords, home safety, host registration, session PIN).
  - The stale "future session PIN" answer was corrected.
  - VOLT never approves bookings or listings.

## Migration plan (each step needs owner approval)
1. **Deploy the backend first** (merge into `production/v1`, then Render auto-deploys).
   - Old records and tokens keep working, with no data migration.
   - Socket requests from every app version then need V1.4's confirmation plus a host-declared dedicated circuit that fits the rating.
2. **Smoke test on production:** `/public/config` shows `dualRole`/`socketGate`; an existing driver and host can sign in; the admin users list shows capabilities.
3. **Optional backfill** (not required for correctness): write `capabilities` from `role` for existing users, in a batched admin script with a dry run first.
4. **Release the V1.4 APK.** Raise `minSupportedVersionCode` only after adoption; the server already blocks unsafe old-client actions.
5. **Rollback:** redeploy the previous backend. V1.4 hides the switch when `dualRole` is absent. Capability fields are inert to old code, and claims keep `role`.

## Blockers / pending
- **Owner approval** to deploy the backend, enable host registration, or run any backfill.
- **Hosts with socket connectors on a 32 A wallbox listing** are blocked for socket requests (current or power exceeds the socket rating). They need a separate socket listing/rating model if both are offered.
- Telugu/Hindi strings for V1.4; device acceptance (mode switching, map and orb placement, large fonts); Robolectric UI tests on your PC.
- The host can't remove a capability themselves (support/admin task, by design for now).

```powershell
cd "$env:USERPROFILE\NEARVOLT-EV"
git fetch origin; git checkout upgrade/v1.4-dual-role; git pull --ff-only
cd android
if (-not (Test-Path app\src\prod\google-services.json)) { throw "app\src\prod\google-services.json missing" }
if (-not (Test-Path keystore.properties) -and -not $env:NV_KEYSTORE_FILE) { throw "Release key not configured (android\keystore.properties or NV_KEYSTORE_* variables)" }
.\gradlew.bat clean testDevDebugUnitTest lintDevDebug assembleProdRelease "-PNV_PROD_API_BASE_URL=https://nearvolt-api-0rxa.onrender.com/"
if ($LASTEXITCODE -ne 0) { throw "Build or tests failed" }
$bt   = (Get-ChildItem "$env:LOCALAPPDATA\Android\Sdk\build-tools" | Sort-Object Name | Select-Object -Last 1).FullName
$out  = New-Item -ItemType Directory -Force -Path ..\release-1.4.0
$apks = @(Get-ChildItem app\build\outputs\apk\prod\release\*-release.apk)
if ($apks.Count -ne 4) { throw "Expected 4 signed APKs, found $($apks.Count). Unsigned output means the release key was not picked up." }
foreach ($a in $apks) {
  $dest = Join-Path $out ("NEARVOLT-EV-1.4.0-" + ($a.BaseName -replace '^app-prod-|-release$','') + ".apk")
  Copy-Item $a.FullName $dest -Force
  "== $(Split-Path $dest -Leaf)"
  & "$bt\apksigner.bat" verify --print-certs $dest | Select-String "Signer #1 certificate SHA-256"
  & "$bt\aapt2.exe" dump badging $dest | Select-String "package:|native-code"
  "SHA-256: " + (Get-FileHash $dest -Algorithm SHA256).Hash
}
```
